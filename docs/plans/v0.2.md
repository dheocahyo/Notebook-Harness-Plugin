## User decisions (asked fresh, 2026-09-28)

- **FR-10 plan:**
  - /nh:plan gives an editable list of 5–12 steps.
  - "run next N" asks approval for the batch once, in chat ("Run steps 3–5 in one reply?").
  - After the user's yes, nh writes and runs those cells in one reply, with a short report after each. It stops at the first error or "check this" warning.
  - This applies to any preset.
- **FR-12 guardrails:**
  - **Cells:** the gateway refuses the cell with a question in chat. After the user's yes, the retry of that exact cell is accepted once.
  - **Shell and WebFetch outside nh:** Claude Code's Allow/Deny dialog, raised by a hook.
  - **Scope:** pip install, network calls, writes outside the project, and re-running more than one existing cell.
  - **Multi-rerun:** add the ability to re-run several cells, for example "re-run the stale cells". nh lists them and asks. After a yes it runs them in order and stops at the first error.
- **FR-14 secrets:**
  - A cell that prints env vars or credentials is refused by a hard lint rule.
  - Redaction covers only what Claude sees. The .ipynb keeps the real outputs.
- **FR-9 explain:**
  - A message that starts with "explain" and has no change verb (fix/change/add/update/rewrite/refactor/make) is explain-only.
  - It gets a numbered walkthrough in chat, and the gateway refuses notebook changes in that turn.
  - `/nh:explain` works too.
- **FR-13 presets:**
  - `[preset] level = "junior" | "senior"`, default junior. /nh:init doesn't ask.
  - Switch from the command line with `nhctl preset senior|junior`.
  - The preset sets explanation depth and the comment budget: junior 1 comment per 8 lines (today's default), senior 1 per 16. The budget is advisory, and an explicit `[lint] comment_ratio` overrides it.
- **FR-11 review:**
  - /nh:review runs a copy of the notebook in a separate kernel (extending `nhctl fresh-run`) and keeps going past errors.
  - It reports every failing cell, hidden-state dependencies, cells over 40 lines as `src/` candidates (`[lint] max_cell_lines = 40` today), and a one-page intent summary.
  - Output goes to chat and to `.nh/reviews/`.
  - The live kernel and the notebook are never touched.

### D0. One mechanism for FR-9, FR-10 and FR-12

**a. Classify every human message in the hook.**
- `hk/nh_hooks/prompt_submit.py` `handle` calls a new pure module, `gw/_shared/intent.py` (py3.9, stdlib, shared by hooks and gateway).
- The result goes into the turn record (`gw/_shared/turn_record.py`, `opened()` / the `read` whitelist) as these optional fields:
  - `mode`: explain | plan | ask | None
  - `request`: {batch, n} | {rerun_stale} | None
  - `answer`: yes | no | None
  - `prev_turn_id`
  - `prev_request`
- `RECORD_VERSION` stays 2. Absent keys read as None, `aliased` keeps the fields, and `orphan` clears them.
- The classifier matches whole words, case-insensitive:
  - **explain:** first word "explain", or starts with "/nh:explain", and no change verb.
  - **plan:** starts with "/nh:plan".
  - **batch:** "run (the) next N" or "run steps a-b", with n ≥ 2. Sets mode ask.
  - **rerun_stale:** "re-run (all) (the) stale (cells)". Sets mode ask.
  - **answer:** the whole trimmed message matches a small yes set or no set. "go" counts as yes only when it is the whole message.
- On a classifier exception, the fields are None, the record is still written, and a `classify_failed` event is logged. Prompt text is never stored.
- **Mid-turn messages** (user, 2026-09-29, after V16). A message absorbed mid-turn arrives with prompt_id == the record's turn_id, and it can only tighten:
  - mode explain, plan or ask is applied for the rest of the turn;
  - a batch or rerun_stale request is kept for the next reply;
  - a yes/no is never an answer;
  - prev_turn_id, prev_request and pending stay as they are;
  - there's no new cell budget, and the one-cell reminder isn't re-injected.

  C1 updates the §6.0 (a) "user decision pending" bullet to say this.

**b. Pending question and one-shot grant, in the gateway.**
- **Storage.** The ledger (`gw/policy/turn.py` `TurnLedger`) goes to `{"v":2, "turns", "pending"}` and still loads v1. Pending is `{kind: cell|rerun, key: sha256(raw text), turn_id, ts}`: hashes only, never the question.
- **One question at a time.** The first ask in a turn wins; a second ask gets E122 "already waiting for the user's answer".
- **Clearing.** A successful gated write in that turn clears pending.
- **Next human turn.** If `answer == "yes"` and `pending.turn_id == prev_turn_id`, the call with the exact matching key is accepted once. Any other answer drops pending.
- **Batch and re-run-stale requests** are granted when `answer == "yes"` and `prev_request` is set. The grant goes into new `TurnState` fields: `batch_total`, `batch_stop`, `rerun_plan`, `rerun_stop`, `rerun_stale`.
- **Locking.** Every grant check and slot use happens inside `svc.locks.hold`.
- **Trust boundary.** The gateway trusts the hook-written record against a model that follows instructions; it is not an adversarial boundary.
  - `file_guard` already denies `.nh/`.
  - `SHELL_NH_STATE_WRITE` (`gw/_shared/patterns.py`) gains a python `open('.nh/…','w'|'a')` pattern.

**c. E110 gets exactly two explicit, gateway-enforced exceptions:** an approved batch and an approved re-run list. `design.md §0` says so.

**d. New codes (all grep-verified free):**

| Code | Meaning |

| E122 | Needs the user's yes; Next = the exact question to ask |

The existing E102 gains the detail "nh missed this message; send it again".

### D3. FR-10 /nh:plan and the approved batch
- **Plan.** `sk/plan` sets mode plan, so there are no writes that turn. It gives 5–12 steps in the planning.md format; the list lives in chat. Edit messages re-print the list.
  - "go" means step 1, as a normal turn.
  - "run next N" or "run steps a–b" takes the batch path.
- **T1 ("run next 3").** mode ask, so E109 applies. The reminder tells Claude to ask one question and write nothing. If n > `[turn] max_batch`, Claude asks for at most max_batch.
- **T2 ("yes").**
  - The first gated call sets `batch_total = min(n, max_batch)`.
  - The E110 check (`gw/tools/write.py` ~L671) uses `state.batch_total or max_code_cells`.
  - The per-cell report shows `turn=k/N batch` via `machine_line` (`gw/tools/common.py`) and `render.next_block`.
- **Stop.** `report_run` sets `batch_stop` on status != ok, including running/queued, or a non-empty `check_this`; any E12x also stops it. After that, new cells and retries get E123 "report the batch and wait".
- **Ultracode.** `workflow_guard` allows up to N sequential qa-cell launches in a grant turn. The single `TurnState.writer_run` becomes per-slot: the next run may own slot k+1 only after slot k's cell is ok.
- **Config.** `[turn] max_batch = 5` goes in defaults.toml and harness-toml.md.

### D5. FR-12 multi re-run
- **Schema.** `nh_run` gains `then: list[str] = []`. Update TOOL_DEFAULTS, the `scripts/dump_tools.py` snapshots and the eval tool list.
- **Without a grant.** A non-empty `then` records pending {rerun, sha(notebook|ids)} and raises E122. The question lists "[n] title" in order and says the run stops at the first error.
- **"Re-run the stale cells".**
  - The request turn is mode ask: Claude lists the stale cells (outline view) and asks.
  - In the yes turn, `[cell_id] + then` must equal the StaleStore stale list in notebook order (`gw/state.py`); otherwise E124.
- **Accept.**
  - `state.rerun_plan = then`.
  - Each next `nh_run(cell_id=rerun_plan[0])` is accepted before the E114 check (`gw/tools/run.py` ~L79) inside `locks.hold`, and pops the head.
  - Out of order: E124.

- **Single re-runs** are unchanged.

### D7. FR-14 lint rules
- **L011 secret_print (hard).** A cell is refused when it displays env-sourced values as the last expression, print, display, repr, or a printed f-string.
  - Sources: `os.environ[...]`/`.get`/`getenv`/`dict(os.environ)`/`.copy()`/`dotenv_values`, plus names assigned from these (dataflow).
  - Magics: `%env` without `=`, `!env`, `!printenv`, `!set`, `!export -p`, `!echo $X`.
  - Exempt: `len`, `bool`, `is (not) None`, `in os.environ`, `.keys()`.
  - The first-cell.md code must lint clean.
- **L014 secret_name (hint).** Displaying identifiers whose underscore-split parts include api_key, secret, password, token, credential(s) or private_key. "tokens", "tokenizer" and "author" don't match.
- **E125.** add/edit refuses code containing `[redacted:`. Next: read the value from the env without printing it, or ask the user to edit that line in JupyterLab.

**Ultracode.** Each chunk runs as one small workflow, fewer than 10 agents:

- what it may skip: nothing in the chunk scope, unless a gating spike failed and the plan names the fallback;
- what it must not do: commit, touch dev/sandbox, change pinned text, or cap code or chat length;
- that a user message relayed mid-run means stop and return, never "skip".

I post progress at each phase boundary, with no long silent waits.
